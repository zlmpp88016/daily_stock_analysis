# 可定制技术指标策略回测功能 PRD（简版）

> 更新时间：2026-04-13
> 目标：在现有项目中新增“用户可配置技术指标规则并执行历史回测”的能力

---

## 1. 背景

当前项目已经具备以下相邻能力：

- 日常股票分析与 AI 决策仪表盘
- Agent 问股与自然语言策略提示
- 基于历史分析记录的“AI 回测验证”

但用户希望的是另一类能力：

- 自定义 MA5、MA20、MA30、MACD、KDJ、BOLL 等技术指标参数或条件
- 自定义买入条件与卖出条件
- 指定股票、指定起始时间，例如 `2024-01-01`
- 按策略在历史行情中逐笔回测
- 输出交易明细、累计收益率、胜率、最大回撤等指标

这属于“策略交易回测系统”，与现有“历史 AI 建议评估回测”不是同一个功能。

---

## 2. 需求目标

新增一套独立的“策略回测”能力，支持用户：

1. 配置技术指标及其参数。
2. 配置买入规则与卖出规则。
3. 指定股票、时间区间、初始资金、手续费、滑点。
4. 基于历史日线执行回测。
5. 查看逐笔交易结果与汇总绩效指标。

---

## 3. 现状调研结论

### 3.1 当前已有能力

- 项目主流程与 Agent 架构已经成熟，适合作为新功能挂载点。
- 当前存在技术分析模块，已实现固定均线、MACD、RSI、量能、支撑压力、综合买卖信号。
- 当前存在回测模块，但回测对象是历史 `AnalysisHistory` 记录里的 `operation_advice`、止盈止损和后续行情表现。
- 前端已有独立“回测”页面，后端已有回测 API、Service、Repository、数据库表。

### 3.2 当前不支持的部分

当前项目 **不支持** 以下能力：

- 不支持用户定义“结构化可执行”的买卖规则。
- 不支持把自然语言策略 YAML 直接转成可执行回测规则。
- 不支持指定 `start_date / end_date / buy_rules / sell_rules / indicators` 后运行策略回测。
- 不支持输出真正的逐笔交易账本和资金曲线。
- 不支持 KDJ、BOLL 的可执行指标计算与规则判断。
- 不支持多指标组合条件的规则引擎。

### 3.3 关键判断

结论：**项目目前只有“技术分析”与“AI 回测验证”，没有“可定制指标策略历史回测”能力。**

## 4. 现有系统证据点

以下文件说明了当前能力边界：

### 4.1 技术分析能力

- `src/stock_analyzer.py`
  - 已实现固定均线、MACD、RSI、量能、支撑压力、综合信号。
  - `MACD` 参数固定为 `12/26/9`。
  - `RSI` 参数固定为 `6/12/24`。
  - 没有 KDJ、BOLL 的执行逻辑。

- `src/agent/tools/analysis_tools.py`
  - `calculate_ma` 工具支持传入自定义均线周期，例如 `5,10,20,30,60`。
  - 但该能力只停留在 Agent 工具层，没有进入统一策略执行或回测链路。

- `data_provider/base.py`
  - 数据层默认只补充 `ma5 / ma10 / ma20 / volume_ratio` 等基础指标。
  - 不是一个可扩展的指标引擎。

### 4.2 策略系统能力

- `strategies/README.md`
  - 当前策略系统是“自然语言 YAML 策略文件”。
  - 这些策略用于引导 Agent 分析，不是可执行回测规则。

- `src/agent/skills/base.py`
  - `SkillManager` 负责加载内置和自定义 YAML 策略。
  - 本质是提示词注入，不是规则引擎。

### 4.3 回测系统能力

- `src/core/backtest_engine.py`
  - 当前引擎根据 `operation_advice` 推断 `long/cash` 和方向预期。
  - 再用未来若干日的 OHLC 数据评估建议是否正确。
  - 这是“建议评估引擎”，不是“策略交易引擎”。

- `src/services/backtest_service.py`
  - 回测入口从 `AnalysisHistory` 中获取候选记录。
  - 回测结果写入 `BacktestResult`、`BacktestSummary`。

- `src/repositories/backtest_repo.py`
  - 回测候选数据来源是 `AnalysisHistory`。
  - 说明当前回测前提是“先有一次 AI 分析记录”，而不是用户临时构造一套规则。

- `api/v1/schemas/backtest.py`
  - 当前回测请求只支持：
    - `code`
    - `force`
    - `eval_window_days`
    - `min_age_days`
    - `limit`
  - 没有任何策略配置字段。

- `apps/dsa-web/src/pages/BacktestPage.tsx`
  - 当前页面只支持股票代码过滤、窗口天数、强制重跑。
  - 页面目标是“执行回测以评估历史分析准确率”，不是策略编辑与策略回测。

### 4.4 文档与实现存在偏差

- `vibecoding/project-struct/03-Agent论股功能详解.md`
  - 文档提到 KDJ、布林带、历史回测集成。
  - 但代码侧并没有对应的完整可执行实现。
  - 因此需要将本需求视为“新功能”，而不是“补 UI 即可启用的隐藏能力”。

## 5. 产品范围

### 5.1 MVP 范围

第一阶段建议只做：

- 单股票
- 日线回测
- Long-only
- 单一资金账户
- 固定执行模型：信号日收盘判定，下一交易日开盘成交
- 支持指标：
  - MA
  - MACD
  - KDJ
  - BOLL
- 支持规则：
  - 上穿 / 下穿
  - 大于 / 小于
  - 且 / 或
- 支持结果：
  - 逐笔交易记录
  - 累计收益率
  - 胜率
  - 最大回撤
  - 交易次数
  - 平均持仓天数
  - 资金曲线

### 5.2 暂不纳入首期

以下能力不建议在第一期实现：

- 多股票组合回测
- 动态仓位管理
- 参数自动寻优
- 网格交易、海龟交易等复杂系统
- 分钟级 / Tick 级回测
- 做空与融资融券
- 自然语言策略直接自动编译成规则

## 6. 功能方案总览

建议新增一套独立的“策略回测”模块，不直接复用当前 `BacktestService` 的业务语义。

### 6.1 设计原则

- 保持现有 `AI 回测验证` 不变。
- 新增 `策略回测`，与现有回测并行存在。
- 先做结构化规则，不做自然语言规则解释执行。
- 指标计算、规则判断、回测执行三层分离。
- Service 层复用已有数据库日线数据与数据补全能力。

### 6.2 建议新增模块

- `src/strategy_backtest/models.py`
  - 请求模型、指标配置、规则配置、交易记录、汇总结果

- `src/strategy_backtest/indicators.py`
  - 统一指标计算引擎
  - 实现 `MA / MACD / KDJ / BOLL`

- `src/strategy_backtest/rules.py`
  - 规则表达式和条件判断
  - 支持 `cross_over / cross_under / gt / lt / and / or`

- `src/strategy_backtest/engine.py`
  - 逐日遍历历史数据
  - 生成买卖信号
  - 产出交易记录、收益率和资金曲线

- `src/services/strategy_backtest_service.py`
  - 编排数据读取、补数、执行、持久化

- `api/v1/schemas/strategy_backtest.py`
  - 新 API 请求与响应模型

- `api/v1/endpoints/strategy_backtest.py`
  - 新增策略回测接口

## 8. 数据与执行模型

### 8.1 数据来源

- 优先复用本地数据库中的历史日线数据。
- 若区间数据不足，则复用现有数据补全逻辑，从 `DataFetcherManager` 拉取缺失历史行情。

### 8.2 执行规则

建议第一期采用统一模型：

- `T` 日收盘后根据指标和规则判定信号。
- `T+1` 交易日开盘价成交。
- 买入后只允许持有 1 笔仓位。
- 卖出后资金回到账户现金。

这样可以避免未来函数，也便于测试和解释。

### 8.3 输出结果

每次回测至少输出：

- 回测参数快照
- 指标参数快照
- 买卖规则快照
- 逐笔交易记录
- 资金曲线
- 汇总统计

## 10. 数据库存储建议

不建议把新功能直接塞进现有 `backtest_results` / `backtest_summaries`，因为语义不同。

建议新增表：

- `strategy_backtest_runs`
  - 一次回测任务的参数、状态、汇总结果

- `strategy_backtest_trades`
  - 每一笔交易的买卖时间、价格、收益

- `strategy_backtest_equity`
  - 每日账户净值、回撤、持仓状态

这样可以和现有 `AI 回测验证` 并存，边界清晰。

## 11. 分阶段实施计划

### Phase 1：指标引擎

目标：

- 建立统一指标计算模块
- 实现 MA、MACD、KDJ、BOLL
- 为后续规则引擎提供标准字段输出

交付：

- `indicators.py`
- 指标单元测试

### Phase 2：规则引擎

目标：

- 定义结构化规则格式
- 支持基础布尔组合和技术指标条件

交付：

- `rules.py`
- 规则解析与规则执行测试

### Phase 3：回测引擎

目标：

- 基于历史日线生成交易信号
- 输出交易账本与收益统计

交付：

- `engine.py`
- 逐笔交易测试
- 绩效统计测试

### Phase 4：Service + API + DB

目标：

- 接通后端服务层和数据库存储
- 提供可调用 API

交付：

- `strategy_backtest_service.py`
- API schema 和 endpoint
- 数据表迁移
- 接口测试

### Phase 5：前端页面

目标：

- 提供策略回测配置界面与结果展示界面

交付：

- 新页面或新 Tab
- 表单、结果卡片、交易记录表、资金曲线

## 12. 测试策略

### 12.1 单元测试

- MA / MACD / KDJ / BOLL 数值正确性
- 规则判断正确性
- 金叉/死叉/突破/跌破等边界场景

### 12.2 集成测试

- Service 层读取数据库数据并执行回测
- 数据不足时自动补数
- 回测结果落库正确

### 12.3 前后端联调测试

- 表单参数校验
- 错误提示
- 空结果场景
- 大区间回测的性能和响应表现

## 13. 风险与注意事项

### 13.1 主要风险

- 文档中已有 KDJ/BOLL 描述，容易误判为“已支持”，实际代码未落地。
- 如果直接复用现有 `BacktestService`，会把“AI 建议评估”和“策略交易回测”混在一起，导致语义混乱。
- 如果首期就支持自然语言策略回测，规则解释会很不稳定。

### 13.2 应对策略

- 新功能独立命名为“策略回测”。
- 首期只支持结构化规则。
- 首期只支持单股票、日线、long-only。
- 后续再考虑与 Agent YAML 策略系统做桥接。

---

## 14. 验收标准

满足以下条件后，认为 MVP 可上线：

1. 用户可配置 MA、MACD、KDJ、BOLL 参数。
2. 用户可配置买入规则和卖出规则。
3. 用户可指定股票与回测时间区间。
4. 系统可生成逐笔交易记录。
5. 系统可输出累计收益率、胜率、最大回撤、交易次数、平均持仓天数。
6. 前端可展示回测参数、结果概览、交易明细和资金曲线。
7. 单元测试与集成测试通过。

---

## 15. 最终结论

这个需求在当前项目中应被视为一个 **新增功能模块**，而不是对现有回测页面的小改造。

推荐实施路径：

- 保留现有 `AI 回测验证`
- 新增独立 `策略回测系统`
- 先做结构化规则版 MVP
- 后续再与 Agent 策略 YAML 和自然语言能力做融合
